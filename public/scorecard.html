Tote scorecard

How well Tote does its job, measured the same way every time, so a change can be compared with what came before. Live runs send made-up homes to the real models and grade what Tote did to the home, not the words it used. Nothing in your real home is read or changed.

The current version

Every trial of the version that is live now, pooled across nights.

Over time

Each point is one finished run. Regression tasks are things Tote already does and should stay near 100%. Capability tasks are things it is learning to do, so they start low: that line is the hill to climb.

Read the failures

Scores are only as good as the tests. For each failure, say whether Tote got it wrong or the test was unfair. Unfair tests are bugs in the test to fix, and the share of them is shown above as "tests found unfair".

With real people

From everyday use of the app, week by week. A miss is an undo, a correction, saying the same thing twice, a "Not right?" or something Tote could not find. Reminders are useful when they lead to the item going on the list. Pace error is how many days off Tote's learned "you buy this every N days" was, measured when the item was bought again.

Offline scores

Recorded with npm run track before each change is pushed: the router on phrasings it was never taught; world groceries (receipt lines from 20 stores and delivery apps Tote was not tuned on: knowing the item, where it goes, how long it keeps, allergy and diet warnings, units); and how well the learned pace times reminders across 1,000 simulated households.

The weekly loop

  1. Open this page. Look at what broke, and read the failures. Mark each one as Tote's mistake or an unfair test.
  2. On the review page, say what should have happened for real conversations that went wrong. Each becomes a task here.
  3. Fix the prompt, router or code. Run npm test and npm run track, then push.
  4. The new version is checked automatically within minutes of the deploy, and again on the next two nights for consistency.
  5. When a capability task passes every trial, move it to the regression suite (set "suite": "regression" in public/evals/cases.json) and write a harder one.
